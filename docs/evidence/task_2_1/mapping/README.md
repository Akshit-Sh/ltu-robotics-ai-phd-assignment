# Task 2.1 — Mapping Evidence

## Implementation
- Library: slam_toolbox
- Mode: mapping
- Input scan topic: /r0/scan
- Odometry frame: r0/odom
- Base frame: r0/base_footprint
- Map frame: map
- Configured resolution: 0.05 m/cell

## Saved map
- Occupancy image: inspection_map.pgm
- Metadata: inspection_map.yaml
- Visualisation: inspection_map.png
- Dimensions: 152 x 160 cells
- Nominal physical extent: 7.60 x 8.00 m
- Approximate image-pixel classification: occupied 3.4%, free 60.1%, other/unknown 36.5%

The pixel percentages are approximate image-based classifications, not independently validated occupancy-grid statistics.

## Scope and limitations
The saved map and configuration demonstrate a robot-specific 2D mapping pipeline using r0's LiDAR and odometry. Multi-robot map merging was not implemented or demonstrated. Map accuracy against ground truth was not independently evaluated.

## Reproducing the mapping workflow

The configuration used for the robot-specific mapping setup is
`config/slam_r0.yaml`. It configures SLAM Toolbox in mapping mode, subscribes
to `/r0/scan`, uses `r0/odom` and `r0/base_footprint`, and publishes the map
in the `map` frame. The configuration uses simulated time and a map resolution
of 0.05 m/cell.

Build and source the workspace first if the package has not already been built:

```bash
source /opt/ros/humble/setup.bash
cd ~/ltu_rai_assignment/ros2_ws
colcon build --packages-select multi_robot_sim --symlink-install
source install/setup.bash
```

Start the Gazebo simulation in one terminal:

```bash
source /opt/ros/humble/setup.bash
source ~/ltu_rai_assignment/ros2_ws/install/setup.bash
export TURTLEBOT3_MODEL=burger
export LIBGL_ALWAYS_SOFTWARE=1
ros2 launch multi_robot_sim multi_robot.launch.py
```

In a second terminal, start SLAM Toolbox:

```bash
source /opt/ros/humble/setup.bash
source ~/ltu_rai_assignment/ros2_ws/install/setup.bash
ros2 launch slam_toolbox online_async_launch.py \
  slam_params_file:=$HOME/ltu_rai_assignment/config/slam_r0.yaml \
  use_sim_time:=true
```

Allow the robot to observe and traverse the environment while checking that
`/r0/scan`, the required TF transforms, and the `/map` topic are available.
The configuration is specific to `r0`; it does not merge maps from all robots.

After collecting sufficient observations, save the map from a third terminal:

```bash
source /opt/ros/humble/setup.bash
source ~/ltu_rai_assignment/ros2_ws/install/setup.bash
cd ~/ltu_rai_assignment
ros2 run nav2_map_server map_saver_cli -f maps/inspection_map
```

This save command writes the occupancy image and metadata to the selected
output prefix. The reproduction commands describe the intended workflow;
they do not establish that the historical committed map was generated by
this exact sequence. Verify the live launch, map publication, and save
operation before treating a new run as reproduced.

## Interpretation and limitations

The saved map is a partial 2D occupancy representation. Approximate image-based
classification gives 60.1% free, 3.4% occupied, and 36.5% other/unknown pixels,
or approximately 63.5% known coverage. These are not independently validated
occupancy-grid statistics. The map's geometric accuracy has not been measured
against ground truth. Multi-robot map merging was not implemented or
demonstrated, and the A* navigation planner uses static Gazebo SDF collision
geometry rather than this saved occupancy map.
